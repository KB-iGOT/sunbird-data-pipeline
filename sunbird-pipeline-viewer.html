How This Pipeline Works

Apache Flink — A stream processing engine. Each "job" is a continuously running program that reads events as they arrive, processes them, and writes results. No batch delay.

Apache Kafka / Redpanda — A message bus with named "topics" (like mailboxes). Job A drops events into a topic; Job B reads from that topic. This decouples each stage so they run independently.
Local dev: runs Apache Kafka 3.7 (KRaft) with the Kubernetes Service named redpanda — so all Flink configs point to redpanda:9092 and work unchanged when the image is swapped to real Redpanda in production. Redpanda is a separate C++ product (not a newer Kafka) that is 100% Kafka wire-compatible.

Redis — An in-memory key-value store used for two things: (1) Deduplication — "have I seen this event before?", and (2) Metadata caching — "what city is device X from?"

Apache Druid — A time-series analytics database where final validated events are stored for dashboards and reports. Both druid.events.telemetry and druid.events.summary feed into Druid — not cloud storage.

SECOR — A separate Pinterest-era archival tool that reads certain Kafka topics (telemetry.raw, telemetry.denorm, etc.) and writes them as flat JSON files to S3. This is the long-term backup path — separate from the analytics path.
